# 云生产品路线图

从业务结果倒推能力建设顺序，让路线图表达选择、依赖和验证条件。默认使用简体中文。

## 何时使用

- 规划云生季度、半年度或版本路线图。
- 在多个 CMS、模型、协作和资产能力之间做取舍。
- 将交付复盘和用户反馈转成可执行里程碑。

不用于承诺具体发布日期、替管理者分配资源或绕过评审。

## 输入

- 时间范围、业务目标、目标用户和约束。
- 已验证的问题、证据、严重度、频率和当前替代方案。
- 候选能力及其预期结果、成本、风险和依赖。
- 团队容量、关键角色、外部系统、数据与合规依赖。
- 当前指标基线、目标、计算公式和质量护栏。
- 已作出的产品判断、暂缓项和非目标。

缺失不等于 0。事实、推算、估算和外部基准分栏；涉及数字的路线图依据必须带周期、范围、分子/分母、公式和 source_id。source_grade 中 A=系统/账单/正式记录，B=带日期可复核截图或人工台账，C=用户陈述，D=外部基准，N=无证据；claim_method 使用 direct/derived/estimated/benchmark/unknown。对外承诺状态默认 false。

## 强约束

- 路线图条目以结果或能力命名，不以页面和按钮堆砌。
- Now 只放已验证、容量可承接且依赖明确的项目。
- Next 必须写进入 Now 的证据门；Later 不是暗含承诺。
- 日期、Owner 和资源只有在来源明确时填写。
- 每项能力同时记录不做的代价、机会成本与停止条件。
- 模型升级本身不是结果；必须连接到质量、成本、周期或用户任务。

## 工作流

1. 锁定规划周期与北极星结果，列出非目标。
2. 统一候选项粒度，关联用户问题和证据。
3. 从影响、置信度、成本、风险、依赖和战略一致性评估候选项。
4. 先排除不满足门槛的项目，再按依赖和学习顺序排序。
5. 形成 Now/Next/Later，并标记决策门和回退方案。
6. 把 Now 拆成里程碑、Owner、输入、输出、验收和指标。
7. 做容量与风险检查；超载时明确删除或延期，而非压缩工期。
8. 设定复盘节奏和触发重排的事件。

## 固定输出

1. 规划周期、目标用户、业务结果与非目标。
2. 候选项评分及证据。
3. Now/Next/Later 路线图。
4. 每项能力的问题、产品机制、目标指标、基线缺口、依赖和风险。
5. Now 里程碑：Owner、时间窗、决策门、验收与停止条件。
6. 容量与关键路径检查。
7. 暂缓/拒绝项及理由。
8. 复盘日期与重排触发条件。

## 停止条件

若目标结果、真实容量或关键依赖缺失，只能输出候选路线图和待确认项，不得写成已承诺计划。修改真实排期、创建任务或通知团队需要用户另行授权。
