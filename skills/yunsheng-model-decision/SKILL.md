# 云生模型选型

将“用哪个模型”改造为一个可复现的镜头级决策：先明确场景与失败代价，再用同一套样例评测质量、可控性、成本和风险。

## 适用

- 为图像、视频、口型、语音、音乐、抠像或后期任务选择模型。
- 为不同镜头设计主路由、备用路由和人工兜底。
- 模型、价格、权限或项目需求变化后重新评估。
- 设计小规模 POC，或追踪可用镜头的实际成本。

## 不适用

- 仅撰写创意 Brief、编排团队任务或进行最终业务验收。
- 用一张公开榜单代替真实镜头测试。
- 未经授权把内部、个人、未公开或受版权保护的素材上传至外部服务。

## 输入

- Approved Brief 和镜头清单，包含时长、主体、动作、镜运、文字、音频、一致性与清晰度要求。
- 候选模型、当前可用版本、账户权限、地域和数据传输限制。
- 同一测试集上的实际样例、失败类型、可用率、尝试次数、耗时和实际账单。
- 最新官方能力、限额、商用条款和价格证据，以及内部安全/采购要求。
- 用户指定的质量、成本、时延、可控性、稳定性和风险权重。

## 强约束

- 模型能力、可用性、价格和条款会变化。当用户要求“最新”或要做当期选型时，如可以访问互联网，先核对模型提供方官方页面并记录查询日期；公开榜单只作辅助证据。
- 内部同场景实测优先于营销页面。样例、参数、模型版本、调用日期和评分人必须可追溯。
- 分开图像、视频、口型、声音与后期任务；不设置一个脱离镜头任务的“综合最佳模型”。
- 费用分开标价、试用/折扣、实际账单和内部分摊。价格必须带币种、税口径、时间、规格、来源和已核验/推算/待补证状态。
- 对可用镜头成本使用可复核公式，例如“单次实际成本 × 平均尝试次数 + 相关人工处理成本”；无数据时不填默认次数。
- 不因成本优势忽略肖像、版权、声音克隆、隐私、品牌和数据安全风险。

## 事实契约

- 缺失不等于 0。“未提供”、“无法核验”和真实的数值 0 必须分开。
- 所有定量信息按“事实 / 推算 / 估算 / 外部基准”分栏，不得混写；外部基准另附发布日期与适用条件。
- 数字必须附周期、范围、单位、分母或公式及 `source_id`；无 `source_id` 时仅能记为待补证。
- 来源等级与计算方式分开记录：`source_grade` 中 A=系统/账单/正式记录，B=带日期可复核截图或人工台账，C=用户陈述，D=外部基准，N=无证据；`claim_method` 使用 direct/derived/estimated/benchmark/unknown。
- 本 Skill 生成的选型建议默认为 Draft，不会自动获得对外使用批准；对外引用、发送或发布前必须人工确认。

## 工作流

1. 将镜头拆成可测试的任务单元，定义品质底线、必须控制项和可接受的失败。
2. 列出候选模型及其当期版本，核对权限、输入限制、输出规格、商用条款、数据策略和价格。
3. 设计最小 POC：使用同一测试集、可比参数和盲评条件，记录评分者和失败类型。
4. 按用户确认的权重评估质量、可控性、稳定性、时延、可用镜头成本、接入成本和风险；缺失证据不得赋予虚假分数。
5. 为每类镜头生成主选、备用和人工兜底，并定义何时切换，避免无限重试。
6. 生成建议、不确定性、证据缺口和重测日期，请技术、制作、安全/采购及业务负责人按职责确认。

## 固定输出字段

1. 决策摘要：场景、镜头范围、查询/测试日期、Owner。
2. 镜头任务表：要求、质量底线、可接受失败、风险级别。
3. 候选模型证据表：版本、官方来源、权限、条款、价格和数据日期。
4. POC 设计：测试集、参数、评分维度、权重、评分人、通过条件。
5. 实测结果：样本量、可用率、尝试次数、耗时、实际账单、失败类型和证据状态。
6. 镜头级路由：主选模型、备选模型、人工兜底、切换条件和重试上限。
7. 成本与时延计算：公式、假设、区间、来源和缺口。
8. 建议、适用边界、安全/版权风险、决策人与重测时间。

## 停止与人工确认

- 内部素材或人物数据未获得上传/处理授权时，不进入外部模型 POC。
- 候选模型的版本、价格或商用条款无法核验，或测试条件不可比时，不宣布最终胜出者。
- POC 会产生显著费用、新增供应商或数据跨境/安全风险时，须获得相应授权后执行。
- 最终选型必须由技术可行性、制作质量、安全/采购合规和业务可接受性的对应负责人确认；单一评分不自动产生授权。
